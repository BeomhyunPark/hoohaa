# 규칙 판단 엔진

목록은 [index.md](index.md)다. 공통 규칙은 [center.md](center.md)다. 판단 보류는 [withhold.md](withhold.md)다.

**결정.** 컨디션, 목표, 내일 훈련, 달리는 중 페이스는 러닝 코치가 정한 규칙으로 판단한다. 외부 판단 API(Jev)는 쓰지 않는다. 호출 비용과 API 키가 없다. 같은 입력이면 언제나 같은 답이 나온다.

**결정.** 이 숫자들은 코칭 기본값이다. 의학적인 조언이 아니다. 통증이 있으면 언제나 "계속되면 진료를 받아 보세요." 줄을 보여 준다.

**결정.** 화면 문장은 한국어 해요체이고, 아래 템플릿을 쓴다. `{}` 안은 코드가 채운다. 다른 화면 문장은 [features/copy.md](features/copy.md)다.

## 0. 공통

### 훈련 부하

`load = duration_min × factor`

| 종류 | factor |
|---|---|
| E, 회복 | 1.0 |
| M | 1.5 |
| T | 2.0 |
| I | 3.0 |
| R | 3.0 |
| 레이스 | 3.0 |
| 모름 | RPE/3, 0.7~3 사이로 자른다 |

`ACWR = 최근 7일 load ÷ (최근 28일 load ÷ 4)`

### 기준값

- 안정 심박(RHR), HRV, 수면은 최근 28일 이동 중앙값을 기준으로 한다.
- HRV는 기기가 주는 값 하나만 쓴다. rMSSD나 SDNN 중 하나이고, 둘을 섞지 않는다.
- 기준값을 만든 날이 7일보다 적으면 그 신호는 쓰지 않는다.

### 최대 심박과 존

- HRmax는 최근 90일 기록의 최대 심박이다. 없으면 `208 − 0.7 × 나이`다.
- 존은 HRmax 대비 비율이다.

| 존 | 범위 |
|---|---|
| Z1 | 70% 미만 |
| Z2 | 70~80% |
| Z3 | 80~87% |
| Z4 | 87~93% |
| Z5 | 93% 초과 |

### 강한 훈련과 통증

- 강한 훈련은 T, I, R, 레이스이거나 RPE 7 이상인 운동이다.
- 통증 키워드는 `통증`, `아프`, `아픔`, `찌릿`, `붓`, `부음`, `절뚝`, `저림`, `pain`이다. 메모에서 부분 일치로 찾는다.

## 1. 오늘의 컨디션

선택지는 {그대로 훈련, 강도 낮추기, 휴식}이다. 기능 문서는 [features/condition.md](features/condition.md)다.

### 기록이 적을 때

기록이 14일보다 적으면 RPE와 통증만 본다. "기록이 2주 쌓이면 더 정확해져요."를 같이 보여 준다.

### 바로 휴식

다음 중 하나라도 맞으면 휴식이다.

- 오늘이나 어제 메모에 통증 키워드가 있다
- RPE 9 이상
- RHR ≥ 기준 + 10
- HRV ≤ 기준의 75%가 이틀 연속

### 위험 신호 점수

각 1점이다.

- ACWR > 1.5. 1.8을 넘으면 2점
- RHR ≥ 기준 + 5
- HRV < 기준의 85%
- 수면 < 6시간, 또는 기준의 80% 미만
- RPE 7~8
- 최근 3일 안에 강한 훈련 2회 이상

| 점수 | 결과 |
|---|---|
| 0 | 그대로 훈련 |
| 1~2 | 강도 낮추기 |
| 3 이상 | 휴식 |

신호가 서로 다르면 더 안전한 쪽을 고른다. ACWR < 0.8은 메모로만 보여 주고 점수에 넣지 않는다.

### 문장

- "최근 7일 훈련량이 평소보다 많아요(×{acwr}). 오늘은 강도를 낮춰요."
- "안정 심박이 평소보다 {d}bpm 높아요. 몸이 회복 중일 수 있어요."
- "통증 기록이 있어서 오늘은 쉬어요. 계속되면 진료를 받아 보세요."
- "컨디션 신호가 좋아요. 계획대로 가요."

## 2. 목표 달성

선택지는 {달성 유력, 가능, 어려움}이다. 기능 문서는 [features/goal.md](features/goal.md)다.

- `predicted`는 현재 VDOT로 예측한 목표 종목 기록이다. 계산은 [features/tier-vdot.md](features/tier-vdot.md)다.
- `gap% = (predicted − target) ÷ target × 100`
- 남은 기간의 VDOT 상승은 주당 +0.3이다. VDOT 50 이상이면 주당 +0.15다. 합계는 +4까지다.
- 상승분에 `min(1, 주간 평균 km ÷ 필요 km)`를 곱한다. 필요 km는 10K 25, 하프 35, 풀 50이다.
- `projected`는 `VDOT + 상승분`으로 예측한 기록이다.

| 조건 | 결과 |
|---|---|
| predicted ≤ target | 달성 유력 |
| projected ≤ target | 가능 |
| 그 밖 | 어려움 |

- 풀코스이고 주간 40km 미만이면 한 단계 낮춘다.
- 대회까지 2주 미만이면 상승분 없이 현재 VDOT만 쓴다.
- VDOT가 없거나, 최근 4주에 20분 이상 달린 기록이 3회 미만이면 판단 보류다.
- 비난하는 말은 쓰지 않는다. 어려움이면 `projected`를 현실적인 목표로 제안한다.

### 문장

- "지금 실력으로도 {target} 페이스가 보여요. 꾸준히만 가요."
- "남은 {w}주 동안 꾸준히 훈련하면 충분히 노려볼 만해요."
- "이번엔 {projected} 정도가 현실적인 목표예요. 꾸준히 가면 다음 레이스에서 더 줄일 수 있어요."

## 3. 내일 훈련

E·M·T·I·R 중 1~2개를 고른다. 기능 문서는 [features/tomorrow.md](features/tomorrow.md)다.

### 시기

대회까지 남은 주로 나눈다.

| 남은 주 | 시기 | 질 훈련 |
|---|---|---|
| 12주 초과 | 기초 | E와 R 스트라이드 |
| 12~5주 | 빌드 | T, I |
| 4~2주 | 피크 | 10K는 I, 하프는 T, 풀은 M |
| 2주 미만 | 테이퍼 | 짧은 T나 I. 훈련량 40~60% 줄임 |
| 대회 주 | 대회 주 | E와 짧은 레이스 페이스 |

### 순서

위에서부터 처음 맞는 규칙을 쓴다.

1. 컨디션이 휴식이면 휴식이다. 강도 낮추기면 E다.
2. 최근 48시간 안에 강한 훈련이 있으면 E다.
3. 이번 주 강한 훈련이 2회면 E다. 주간 60km를 넘으면 3회 기준이다. R 스트라이드는 붙여도 된다.
4. 그 밖에는 시기의 질 훈련이다.

### 장거리

최근 7일 안에 주간 거리의 25% 이상인 한 번의 달리기가 없으면 긴 E를 더한다. 하프와 풀은 피크 시기에 M 마무리를 허용한다.

### 상한

주간 거리 대비 T ≤ 10%, I ≤ 8%, R ≤ 5%다. 페이스는 VDOT에서 계산한다.

### 문장

- "어제 강도 높은 훈련을 해서 내일은 이지런으로 회복해요."
- "대회 {w}주 전이라 템포로 레이스 페이스를 익혀요."

## 4. 달리는 중 페이스

선택지는 {유지, 낮추기, 올려도 됨}이다. 기능 문서는 [features/live-pace.md](features/live-pace.md)다.

**결정.** 워치나 폰 기기 안에서 계산한다. 서버를 부르지 않는다. 통신이 끊겨도 동작한다.

- `dev = (페이스 − 목표) ÷ 목표`. 최근 30초 이동 구간으로 본다. +는 목표보다 느리다는 뜻이다.
- 목표 심박 존은 E Z1~2, M Z3, T Z3~4, I Z4~5다.

| 조건 | 결과 |
|---|---|
| 심박이 존 상한보다 3bpm 넘게 높은 상태가 60초 | 낮추기. 페이스보다 먼저 본다 |
| dev < −3%가 30초 | 낮추기 |
| dev > +3%이고 심박이 존 상한 아래 | 올려도 됨 |
| 그 밖 | 유지 |

- E와 회복 달리기에서는 올려도 됨을 쓰지 않는다. 유지로 보여 준다.
- 상태는 30초 이어져야 바뀐다. |dev| ≤ 1.5%가 20초 이어지면 유지로 돌아간다.
- 안내는 60초에 한 번까지다.
- 시작 후 2분, 경사 4% 초과 구간, GPS 튐(5초 안에 페이스 20% 넘게 변함)은 무시한다.

### 문장

- "조금 빨라요. 페이스를 살짝 늦춰요."
- "심박이 높아요. 숨을 고르며 천천히 가요."
- "여유 있어요. 조금 올려도 괜찮아요."
- "좋아요, 지금 페이스 유지해요."

## 나중에 다시 볼 것

**제안.** 판단 이력과 실제 결과(다음 날 실제 운동, "어제 추천한 훈련을 했나요?" 답)가 쌓이면, 학습 모델(예: 미세조정한 Laya)을 다시 검토할 수 있다. 그 전에는 규칙만 쓴다. 바꾸려면 같은 이력으로 규칙과 정확도를 비교한 뒤에 정한다.
